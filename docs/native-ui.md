# Native interface

Updated 2026-09-27 by Codex.

The command surface is a SwiftUI view inside the existing nonactivating AppKit panel. One animated conductor sits beside the current message and controls. Ready and recognition are 360 × 132 pt; ordinary capture, work and attention use 420 pt width. Simultaneous work and capture use 440 pt. Typed entry and shorter answers use 500 pt, while longer answers and details use 540 pt. Height follows the content up to 520 pt and the visible screen limits. Narrow windows yield illustration space to the controls or stack below 320 pt.

Setup has one actionable heading, the missing connection/access explanation and Settings button. There is no second status footer. Work, microphone capture, queue and screenshot counts remain independent. A second live transcript and long transcript use the full width below the compact task header. Short answers put the answer itself beside the illustration, with close, model/details and controls. Longer answers use a compact request header, full-width scrolling text and a 54 pt controls footer. Task controls remain reachable, and typed input stays pinned below the content. Dragging retains the existing bottom-center anchor and upward expansion.

`Sources/Views.swift` owns presentation and existing model bindings. `Sources/ConductorStateView.swift` owns silent local pose playback. `Sources/Main.swift` still owns panel lifecycle and focus. `Sources/CommandPanelGeometry.swift` clamps the window. Settings keep their existing controls, bindings and optional guide.

The selected video supplies seven poses: ready, listening, recognizing, thinking, acting, checking and attention. `Resources/ConductorStates` contains one 360 × 264, 24 fps silent MP4 and PNG poster for each state. The video matte matches panel #17191D with a soft edge. Actual `model.voiceState` selects the pose; missing setup can show attention when idle. The app does not cycle through fake states. State changes crossfade for 220 ms, with at most the current and retiring player. Posters appear immediately and under Reduce Motion; hiding/removing the surface releases playback. Failed or missing media keeps a poster or state symbol. Resources total about 2.7 MB of video and load locally.

The engine behavior is unchanged: Fn/right Option and Option-Space retain their callbacks; typed submission releases keyboard focus before `runTyped`; Stop calls `cancelCurrentTask` without disabling the microphone; Escape closes typing and releases focus; answer dismissal, model changes and conversation reset use their original callbacks. No provider, speech, action, startup, credential or identity code was replaced by this motion/layout update.

Validation uses native renders with sample data, original-source parity checks, build checks and independent visual review. Window geometry checks cover bottom-center expansion, edge clamping and small/secondary displays. An isolated native playback fixture verified rapid state changes, a maximum of two players, still mode, hide/show teardown, and missing/malformed resource fallback. Fixture images are not evidence that real commands completed. Real Fn dictation, focus handoff, pointer passthrough, Spaces and live provider actions remain separate installed-app checks.

On 2026-09-27 the integrated public app built from a fixed source snapshot and passed all twelve `--self-test` groups. The final independent public visual review requested a simpler answer layout and closer grouping of short task controls; these changes were applied and the resulting native renders were inspected. No additional independent review was run after those corrections. The installed app uses the public source and identity; machine-local setup is separate from public code.
